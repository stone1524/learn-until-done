# PLAN.md 单一入口模板

> 设计原则（源自用户实践）：一个领域**只盯这一个文件**，其他文档都是字典，用到才翻。
> 每个学习领域一个目录：`learning/<域名>/`，PLAN.md 在根，笔记进 notes/，产物就地放。
> 格式与一份久经实战的学习排期同构（本 skill 不主动接管已有计划）。

```markdown
# <域名> 学习计划（单一入口）

> 生成日期：YYYY-MM-DD ｜ 档位：A/B/C ｜ 版本：v1（滑期修订升版号并注明改了什么）
> 依据：阶段 0 四要素结论（动机＝…；判据见 §0；每周 ~X h；截止 YYYY-MM-DD，硬底线＝…）
> 节奏原则：每天一个主任务+最小可验证成果；每周唯一主线；每周成果必须**能打开/能演示/能跑通**；外部截止驱动完成率。

## 0. 判据与边界
- 可演示成果清单（逐项可验收，写到能当场演示的粒度）：
  1. …（验收方式：执行 <命令> / 打开 <文件> / 演示 <操作>）
- 量化进度指标：…（如：关卡 0–20 密码链完整；章节练习全敲完；日志覆盖 ≥80% 学习日）
- 明确不学（本领域外，防蔓延）：…

## 1. 逐周计划（C 档不用本节，改用下方半页变体）
### 第 N 周 <日期范围> ｜ 主线：<唯一主线一句话>
- **时间盒（合计 ~X h）**：<事项 h>｜<事项 h>｜…
- **最小成果（周日验收，逐项能跑）**：
  1. …（证据形式：命令输出/截图/录音）
- **资源对应**：<主资料> 第 X–Y 章 / 关卡 a–b

**复盘栏** ｜ 完成情况：＿＿ ｜ 卡点：＿＿ ｜ 下周调整：＿＿

### C 档半页变体（几天速成：替代上面整个 §1/§2，§0/§4 各保留一行）
- 判据：单次产出物 = …（验收：当场能跑通/演示）
- 截止：YYYY-MM-DD（到期处理见「带跑行为规则」）
- 主资料：1 个 + 备胎 1 个
- 待看区（可选）：超范围想法登记一行，不展开

## 2. 砍单规则（仅 A/B 档；某周没做完怎么办）
先砍顺序（nice-to-have 在前）：1.… 2.… 3.…
永不砍（里程碑检验项）：…（允许跨周补完，不允许取消验收）
断更信号：连续两周日志断更 → 触发动力协议（见「带跑行为规则」）

## 3. 待看区（A/B 档默认设；C 档可不设。发现的好资源只登记，不学）
- <名称+一句话为什么好+来源>（登记日期）

## 4. 沉淀（阶段 4 回填）
- 成果物清单与位置：…
- 一句话复盘：哪种做法有效/下次改什么
```

## 填写纪律

1. **最小成果写到「能当场演示」的粒度**：不写「了解 systemd」，写「手写 my-monitor.service 在 ECS 上 enable --now 后重启仍在跑，journalctl 查到输出」。
2. **时间盒逐项列并给合计**，留缓冲；超载就砍内容，不假装装得下。
3. **砍单规则必须在开工前写好（A/B 档）**——滑期当天现想规则必然全线崩。
4. 里程碑检验项验收不过时，只许「顺延补完时间」或「降范围交付」，从不默默删项。
5. 待看区只登记不排期；要学先进排期，不挤占当周主线。
